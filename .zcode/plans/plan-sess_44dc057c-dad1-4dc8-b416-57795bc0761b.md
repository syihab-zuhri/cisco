# Rencana Fitur v1.1.0 — Jaringan Nirkabel + Internet Tersimulasi

## Keputusan desain (default dari rekomendasi saya, karena pertanyaan terbuka)

1. **Internet = Cloud tersimulasi** — perangkat baru "Cloud Internet" yang mewakili dunia luar. Ping ke IP publik (8.8.8.8, 1.1.1.1) dijawab cloud secara deterministik. **Menjaga INV-008/NFR-004**: 100% offline, nol request jaringan eksternal. Internet nyata ditolak karena melanggar aturan project. (Server web/DNS tersimulasi = kandidat rilis berikutnya.)
2. **Nirkabel = Access Point + adapter WiFi** — AP punya port radio ber-SSID + 1 port kabel (uplink). PC & Laptop mendapat port wireless kedua `wla0`. Wireless Router rumahan = kandidat iterasi berikutnya.
3. **Mekanika = SSID saja** — asosiasi otomatis saat SSID cocok (diterapkan saat menyimpan konfigurasi) + drag-to-connect tervalidasi SSID. Radius sinyal & DHCP (fitur P1 blueprint) ditunda.

## Amandemen invarian (dicatat di CHANGELOG §Decisions)

- **INV-003 (amandemen)**: port **ethernet** tetap 1-kabel-1-port. Port **radio** bersifat 1-ke-N (satu AP melayani banyak asosiasi) — hanya sisi klien yang menyimpan binding.
- INV-001/002/004/006/008 tetap terpenuhi (engine tetap murni TS; pesan IPC baru bertipe; asosiasi & jawaban cloud deterministik).

## Fase A — Model & Engine

1. `src/types/network.ts`: `DeviceType` += `'accessPoint' | 'cloud'`; tambah `PortKind`, `kind?: 'ethernet' | 'wireless'`, `ssid?: string` di `PhysicalPort`; `TopologyLink.kind?`; helper `learnsCam(type)` (switch & accessPoint belajar CAM; hub tetap tidak).
2. `src/engine/simulationEngine.ts`:
   - AP = jembatan L2: masuk daftar perantara jalur (`isL2Intermediate`) + belajar CAM pada radio & port kabel.
   - **Cloud**: IP publik milik cloud (8.8.8.8, 1.1.1.1) dikenali `resolveOwner`; saat ICMP tiba di cloud → cloud membalas dengan `TTL = 128 − jumlah router − 1` dan `rtt = router + 1ms` (latensi WAN), log eksplisit. Ping publik tanpa route → gagal "No route" (sudah otomatis: default route `0.0.0.0/0` di-parse oleh longest-prefix yang sudah ada).
3. `src/store/useAppStore.ts`: port default baru (AP: `radio0`+`fa0`; cloud: `wan0`+`wan1`; PC/Laptop: +`wla0`); `DEVICE_LABEL_PREFIX` (AP, Cloud); `connectPorts` menolak port wireless; aksi baru `associateWireless()` (validasi: SSID cocok, klien 1-to-1, AP 1-ke-N) + `syncWirelessAssociation()` saat SSID diubah; `disconnectEdge` paham edge wireless (hanya reset sisi klien, radio AP tetap `up`); `loadTopology` migrasi: tambahkan `wla0` ke PC/Laptop lama yang belum punya.

## Fase B — UI

4. Palet: tombol **Access Point** (ikon Wifi) & **Cloud Internet** (ikon Cloud); warna minimap baru.
5. `DeviceNode`: ikon baru; handle port wireless diberi gaya khas (ungu).
6. Edge baru `WirelessLinkEdge` (garis putus-putus ungu, badge SSID, animasi paket tetap jalan) + registrasi di `TopologyCanvas`; `handleConnect` mengarahkan wireless→`associateWireless`.
7. `DeviceConfigModal`: AP → field SSID radio; PC/Laptop port `wla0` → field SSID + auto-asosiasi saat disimpan; **editor Static Route untuk router** (network/mask/nextHop, pakai aksi `addStaticRoute` yang sudah ada — sebelumnya tak punya UI) agar default route ke cloud bisa dibuat user.

## Fase C — Template, Test, Docs

8. Kategori baru `'Nirkabel'` + 2 template: **"WiFi Hotspot Rumah + Internet"** (cloud—router—AP—laptop/PC, default route siap, ping 8.8.8.8 langsung berhasil) & **"Kantor Nirkabel"** (router—switch—AP—2 laptop WiFi + PC kabel).
9. Test: unit engine (AP bridge + CAM, ping cloud, tanpa route gagal), unit store (asosiasi/validasi SSID/disconnect), integritas template wireless-aware, 1 skenario E2E (template hotspot → ping 8.8.8.8 dari laptop).
10. Docs: modal dokumentasi in-app (kartu fitur + sub-bab simulasi "Nirkabel & Cloud"), README, CHANGELOG v1.1.0.

`type-check` 0 error → unit test hijau (target ≥ 48) → `test:coverage` (engine tetap > 90%) → build → E2E hijau → commit + push ke `main`.
